# Container Image SBOM Snapshot

This directory records SPDX 2.3 JSON software bills of materials for the five Linux/amd64 image references used in `deploy/docker-compose.yml` and `server/Dockerfile`. The snapshot was scanned on 2026-11-27 with Syft 1.57.2 against the platform-specific manifest digests in [`summary.csv`](summary.csv). The official Windows amd64 Syft archive checksum was verified as `0a10e03ffd124c304fd7e7491262dba2e5f68eb12378b106d7525146675b2e3a`.

The SPDX files are tied to the exact platform manifest digests in the summary. Compose and Dockerfile references still use mutable tags, so a later tag pull may produce different contents.

## Scope and limitations

- The inventory contains 392 package records across the five scanned image manifests.
- Syft reported `NOASSERTION` for 169 package records. Five are aggregate OCI root packages with purpose `CONTAINER`, one is the PostgreSQL image's virtual APK dependency group, and 163 are software-component records whose license evidence and redistribution obligations are evaluated individually.
- For the Caddy 2.8.4 binary's 123 Go package records marked `NOASSERTION`, a separate `go-licenses` 2.0.1 review and module-root license-file check mapped 121 records to upstream SPDX licenses. Review of `go.uber.org/zap/exp@v0.2.0` found the full MIT notice in every non-test `exp/zapslog` file at its pinned upstream commit, raising the identified count to 122. The synthetic `command-line-arguments` record is mapped to Caddy's Apache-2.0 main source. The official image history verifies its v2.8.4 release archive SHA-512, and binary BuildInfo identifies the Caddy v2.8.4 module. The [`Caddy Go module crosswalk`](caddy-go-module-crosswalk.csv) records the upstream `cmd/caddy/main.go` hash and image evidence, identifying 123/123 Go records. The Caddy OCI root has purpose `CONTAINER` and aggregates the image contents. The raw [`go-licenses report`](caddy-go-module-licenses.csv) contains 143 Go package paths, including one `Unknown` result.
- For `golang:1.26.11-alpine`, all 10 `cmd/*` and the `go` SBOM package records point to Go 1.26.11. The official tag's root `LICENSE` SHA-256 matches the cached Go 1.26.11 distribution file, identifying BSD-3-Clause for Go-authored source. The [`Go toolchain license crosswalk`](go-toolchain-license-crosswalk.csv) records the 11 package identities and evidence scope. The distribution has 13 separately licensed vendored files under `src/cmd/vendor`; their notices need independent review for the aggregate tool binaries. The raw SPDX still shows `NOASSERTION` for these 11 package records and the aggregate OCI root.
- For Coturn 4.6.3, 20 Debian package SBOM records map by exact package name, version, and architecture to Debian snapshot archives. Every binary archive SHA-1 was verified, and each row records its Debian source package. Seventeen binaries contain a copyright file with a recorded SHA-256. Three GCC runtime packages have no embedded copyright file, so their rows point to the GCC-12 source copyright file and archive hash. Most copyright files use legacy text that needs per-file or package-level SPDX review. The [`Coturn Debian evidence crosswalk`](coturn-debian-license-evidence.csv) records the observed license text and source hashes. Coturn's 26 raw `NOASSERTION` records comprise these 20 Debian packages, five generic package records, and its OCI image root.
- The five generic Coturn CPE records map through the exact image's final `/var/lib/dpkg/status` to installed Debian packages and source versions. The crosswalk pins the file to its OCI layer digest and SHA-256. Four aliases match Debian SBOM package records with explicit SPDX expressions for Bash, gzip, OpenSSL, and util-linux. The Kerberos alias maps to the installed `krb5` source family, whose Debian copyright records still need SPDX mapping. The Coturn OCI root is an aggregate `CONTAINER` record.
- The PostgreSQL 16.16 crosswalk maps the `moby/sys/user` and `tianon/gosu` Go packages to Apache-2.0, `golang.org/x/sys` to BSD-3-Clause, and the server source to the `PostgreSQL` SPDX license. It classifies `.postgresql-rundeps` as a virtual APK group and the OCI root as an aggregate `CONTAINER` record. See [`PostgreSQL evidence`](postgres-license-evidence.csv).
- The PostgreSQL 16.16 image's six `NOASSERTION` records have a dedicated crosswalk. It identifies the Apache-2.0 licenses for `moby/sys/user` and gosu, BSD-3-Clause for `x/sys`, and the PostgreSQL license for server 16.16. It classifies `.postgresql-rundeps` as a virtual APK dependency group and the OCI root as a `CONTAINER` aggregate.
- The `golang:1.26.11-alpine` and `alpine:3.22` records describe build/runtime base images. The final signaling image also runs `apk add ca-certificates wget` and includes project-built Go binaries. That final project image was not built or scanned in this environment because Docker Engine was unavailable.
- The scan covers `linux/amd64`. Other architectures were not scanned.
- Package-level SBOM generation is inventory evidence. It does not replace review of license terms, required notices, source-availability obligations, or distribution conditions.

For updated tags, repeat the registry scan, capture the new platform manifest digest, inspect every `NOASSERTION` entry, and regenerate the inventory before release.
