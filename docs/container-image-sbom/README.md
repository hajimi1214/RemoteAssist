# Container Image SBOM Snapshot

This directory records SPDX 2.3 JSON software bills of materials for the five Linux/amd64 image references used in `deploy/docker-compose.yml` and `server/Dockerfile`. The snapshot was scanned on 2026-11-27 with Syft 1.57.2 against the platform-specific manifest digests in [`summary.csv`](summary.csv). The official Windows amd64 Syft archive checksum was verified as `0a10e03ffd124c304fd7e7491262dba2e5f68eb12378b106d7525146675b2e3a`.

The SPDX files are tied to the exact linux/amd64 platform manifest digests in the summary. `server/Dockerfile` and `deploy/docker-compose.yml` pin their upstream images by the corresponding multi-platform OCI index digest. The amd64 SBOM digest differs from the pinned index digest because it identifies one platform child manifest. All five Docker Hub index digests were queried again on 2026-11-28 and matched the pinned values.

## Scope and limitations

- The inventory contains 392 package records across the five scanned image manifests.
- Syft reported `NOASSERTION` for 169 package records. Five are aggregate OCI root packages with purpose `CONTAINER`, one is the PostgreSQL image's virtual APK dependency group, and 163 are software-component records whose license evidence and redistribution obligations are evaluated individually.
- For the Caddy 2.8.4 binary's 123 Go package records marked `NOASSERTION`, a separate `go-licenses` 2.0.1 review and module-root license-file check mapped 121 records to upstream SPDX licenses. Review of `go.uber.org/zap/exp@v0.2.0` found the full MIT notice in every non-test `exp/zapslog` file at its pinned upstream commit, raising the identified count to 122. The synthetic `command-line-arguments` record is mapped to Caddy's Apache-2.0 main source. The official image history verifies its v2.8.4 release archive SHA-512, and binary BuildInfo identifies the Caddy v2.8.4 module. The [`Caddy Go module crosswalk`](caddy-go-module-crosswalk.csv) records the upstream `cmd/caddy/main.go` hash and image evidence, identifying 123/123 Go records. The Caddy OCI root has purpose `CONTAINER` and aggregates the image contents. The raw [`go-licenses report`](caddy-go-module-licenses.csv) contains 143 Go package paths, including one `Unknown` result.
- For `golang:1.26.11-alpine`, the Go 1.26.11 root `LICENSE` SHA-256 matches the cached distribution file. The [`Go toolchain license crosswalk`](go-toolchain-license-crosswalk.csv) maps 11 `cmd/*` package identities to Go's root BSD-3-Clause license. The [`vendored-license crosswalk`](go-toolchain-vendor-license-crosswalk.csv) maps 13 bundled notices to the versions in `modules.txt`; the official Linux/amd64 Go archive SHA-256 is recorded, all 13 notice files are present in that archive, and their hashes match the exact Go module archives. Twelve are BSD-3-Clause and one is Apache-2.0. `go list -deps` against Go 1.26.11 Linux/amd64 source and the actual archive's binary manifest maps `x/mod`, `x/sync`, `x/sys`, `x/telemetry`, and `x/tools` to binaries that ship in that archive. The other seven license-file components are present in the toolchain source tree but have no import paths in the 10 packaged Go main binaries. The Syft package records remain `NOASSERTION` because the scanner does not describe module imports of each executable. The OCI root record is an aggregate container.
- For Coturn 4.6.3, 20 Debian package SBOM records map by exact package name, version, and architecture to Debian snapshot archives. Every binary archive SHA-1 was verified, and each row records its Debian source package. Seventeen binaries contain a copyright file with a recorded SHA-256. Three GCC runtime packages have no embedded copyright file, so their rows point to the GCC-12 source copyright file and archive hash. The supplemental [`Coturn binary package license review`](coturn-package-license-review.csv) maps six package payloads to exact license evidence, with five SPDX expressions and one upstream public-domain declaration that has no SPDX-listed identifier. Fourteen Debian package records still lack package-level conclusions. The raw SPDX declarations remain `NOASSERTION` and are not rewritten by this supplemental review. Runtime retention of all required notices has not been verified.

  Revalidation on 2026-11-28 matched SHA-1 and SHA-256 digests for all six reviewed Debian binary archives and SHA-256 digests for their six cited copyright evidence files against the ignored local evidence archive. This verifies the source hashes recorded in the table, not the remaining package-to-source license mappings.

  ScanCode Toolkit 32.5.0 matched 12 unique source copyright files. Its [`Debian copyright-text inventory`](coturn-debian-license-text-inventory.csv) records 107 candidate-label rows across these notices, 171 total text-match occurrences passing the score and span thresholds, and the exact Debian binary versions associated with each notice. For the shared Kerberos notice specifically, 24 distinct rule labels generated 58 total raw matches, of which 43 meet the thresholds. The inventory distinguishes 22 license-text candidates from an export-compliance notice and a trademark restriction. These file-scoped matches do not determine package-level SPDX expressions for the remaining binaries. The [`Coturn Debian evidence crosswalk`](coturn-debian-license-evidence.csv) records binary hashes and notice hashes. Coturn's 26 raw `NOASSERTION` records comprise these 20 Debian packages, five generic package records, and its aggregate OCI root.
- The consolidated text inventory links each copyright hash to a Debian source package/version and the associated installed package versions. It does not prove which matched source files were compiled into the individual binary packages; those package-level SPDX declarations remain `NOASSERTION` until the file-to-binary mapping is verified.
- The five generic Coturn CPE records map through the exact image's final `/var/lib/dpkg/status` to installed Debian packages and source versions. The crosswalk pins the file to its OCI layer digest and SHA-256. Four aliases match Debian SBOM package records with explicit SPDX expressions for Bash, gzip, OpenSSL, and util-linux. The Kerberos alias maps to the installed `krb5` source family. A text-match inventory records 24 line-scoped license-text candidates in its legacy Debian copyright file. The matches are not linked to source files in the four runtime packages, so their package-level SPDX declarations remain `NOASSERTION`. The Coturn OCI root is an aggregate `CONTAINER` record.
- The PostgreSQL 16.16 image's six `NOASSERTION` records have a dedicated crosswalk. It maps `moby/sys/user` and `tianon/gosu` to Apache-2.0, `golang.org/x/sys` to BSD-3-Clause, and PostgreSQL 16.16 to the `PostgreSQL` SPDX license. It classifies `.postgresql-rundeps` as a virtual APK dependency group and the OCI root as a `CONTAINER` aggregate. See [`PostgreSQL evidence`](postgres-license-evidence.csv).
- ScanCode's CLI cannot initialize its empty optional plugincode hookspecs with the bundled Pluggy version. The matches were collected using the unmodified `licensedcode` index API. A temporary adapter skips only empty optional hook registration and leaves the 37,542-rule license matcher unchanged. All 12 unique Debian notice files used the same threshold of score at least 90 and span of at least 30 query tokens. Candidate labels are not package-level SPDX conclusions.
- The `golang:1.26.11-alpine` and `alpine:3.22` records describe build/runtime base images. The final signaling image also runs `apk add ca-certificates wget` and includes project-built Go binaries. That final project image was not built or scanned in this environment because Docker Engine was unavailable.
- The scan covers `linux/amd64`. Other architectures were not scanned.
- Package-level SBOM generation is inventory evidence. It does not replace review of license terms, required notices, source-availability obligations, or distribution conditions.

For an image update, deliberately select a new tag and index digest, repeat the registry scan for each supported platform, inspect every `NOASSERTION` entry, and regenerate the inventory before release.
